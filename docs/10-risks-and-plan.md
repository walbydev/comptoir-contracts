# 10 — Risks, lots, and the order of work

- **Status**: closed 2026-10-25 — calendar decided: **as soon as possible**, no dates, order by dependency
- **Block**: 10 (last)

## 1. Risks, ranked by what they would cost

| # | Risk | Impact | Mitigation, already paid or planned |
|---|---|---|---|
| **R1** | **A custom GUI on a `container`** has never been measured — the block-4 choice rests on documentation. **Attempted 2026-10-25 and killed by a signal after nine minutes, with no answer written** — the risk **cannot be closed on this machine**: no player can exist headless (ADR `0050`), so it is closed by the requester's client with the probe mod `spike/gui-probe/`, before any window code is written | high: it is the whole interface — **CLOSED 2026-10-25**: the requester's client showed our frame with no vanilla GUI behind it (ADR `0050`) | lot (b) opens with a **one-hour GUI spike**; fallback is a plain `frame` with no styling, which is ugly but shippable |
| **R2** | **Desync** under real network conditions is not testable here | high: unplayable multiplayer | by construction: one seeded LCG per company in Lua (no engine RNG, no `math.random`), no iteration over unordered tables when writing state; plus a two-client manual session before the first release |
| **R3** | The **buy-back at cost** may flatten contracts if the payout band is too narrow | medium: contracts stop being worth it | the payout factor (1.15) is the single lever; measure it the first hour of playtest |
| **R4** | The **elevator cycle** may feel like a queue manager rather than a rhythm | medium: feel | it is one number in the data file (2 min); the deadline already includes it, so shortening the cycle never invalidates a contract |
| **R5** | **Tier 3 contains one item** (processing unit) — the top of the catalogue is thin | medium: the endgame is short | tiers are derived from the recipe tree, so adding items costs one line each and re-tiers itself |
| **R6** | The **raw-cost model** is a model: it says sulfur is expensive, and a player may disagree | low-medium: it changes the feel of a few lines | reproducible, documented, reviewable; and the scale is one number |
| **R7** | A **save migration** goes wrong after release | high: someone loses a factory | `storage.version` from the first release, a migration path for every schema change, and a test that loads a v1 save in a v2 build |
| **R8** | The **name is taken** on the portal | low: two hours | check `mods.factorio.com` before the first upload, not after |
| **R9** | Shipping with **four criteria never looked at** | medium: an interface nobody validated | `make accept` refuses to be green; the L3 table is dated per release |

Three of these (R1, R2, R9) are the reason the plan is ordered the way it is: the interface comes **after**
the core, so a GUI spike can fail without having cost the economy; and the manual checks are the last gate,
not a formality.

## 2. The lots

No dates. The order is a dependency graph, and each lot ends with something **playable**.

### Lot (a) — the core, playable without a pretty window

Entry: repo skeleton, `info.json`, price data file generated by `tools/cost_table.py`.
Work: counter entity · storage schema v1 · ledger with reserve hold/release/forfeit · companies with a
seeded LCG and a character · contract generator · elevator state machine · counter buy/sell with spread.
Exit: `make test` green headless in both DLC configurations, with the first six L2 tests (A3, A13, A14,
A15, A19, A29). Nothing visual exists yet; a remote interface drives the tests.

### Lot (b) — the interface

Entry: lot (a) green **and** the GUI spike has answered R1.
Work: window frame, two tabs, permanent header · contract rows with digits, bar and contextual button ·
counter tab with prices and the quantity field + presets · the four window states.
Exit: the remaining L2 tests (A1, A2, A7, A9, A10, A18, A26, A28), the static set (A16, A17, A21, A25),
and the four L3 criteria recorded for the first time.

### Lot (c) — finish

Entry: lots (a) and (b) green, and one hour of real play — the first hour where the economy is judged
rather than proven.
Work: migrations + A27 · `make package` + archive scan · `make publish` · the three-check CI · the
portal page in English and French.
Exit: `make accept` green with the L3 table filled, and release **0.1.0**.

The cadrage is finished when: the ten blocks are closed · every decision has an ADR · every acceptance
criterion has a row in `docs/09-tests.md` · the tree in `docs/arborescence.md` matches the plan · the
README says what v1 is in one page · and the tag `v0.1-cadrage` exists on a commit whose tests would
pass if there were code.
